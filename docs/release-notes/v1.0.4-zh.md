# v1.0.4：修复分页会话同步冲突

新版 Codex 会将长会话拆成多个历史文件。此前这些文件可能一直提示“会话关联冲突”：文件已经换成新 Provider，索引却仍保留旧值，再次同步也无法完成。本版修复了这个问题；升级后再同步一次即可补齐符合归属规则的会话。

## 🚀 本次改进

- 同一会话的多个分页文件可以一起同步，文件和索引保持一致。
- 已经发生“文件已同步、索引未同步”的情况，可以再次同步补齐；信息一致后不会重复写入或创建新备份。
- 修复 Windows 长路径与普通路径写法不同引起的关联失败。
- 同步期间新增、被占用或发生变化的文件继续保守跳过，并保留受影响的索引，避免误报全部完成。

## ⬆️ 升级说明

1. 1.0.2、1.0.3 安装版可在应用内检查更新，下载后确认“重启并安装”；也可以退出旧程序后手动安装新版。
2. 便携版请解压到新目录，不要只替换一个 EXE。Legacy .NET 用户也需要完整安装或解压 Electron，旧单 EXE 更新器不能直接完成迁移。
3. 不需要删除 Codex 配置、数据库、历史会话或备份。确认当前 Provider 正确后，再执行一次同步即可。

## 🗂 会话同步怎么处理

- 只有归属明确的分页文件才会一起同步；重复文件、错误路径和多条索引争用同一文件仍会受到保护。
- 出现“部分完成”时，查看被跳过的文件和原因。结束占用或处理文件问题后，重新预览并同步。
- Provider 已一致但会话仍不能继续或 compact 时，需要结合 Codex 的具体报错判断；本次修复只解决 Provider 元数据关联和对齐。

## 🔒 数据处理方式

- 不读取 `auth.json`，不修改聊天正文、其他元数据、`updated_at` 或 `encrypted_content`。
- 实际写入前创建备份，默认保留最近 2 份；需要撤回时可在备份页恢复。无需修改时不创建备份。
- Windows 的路径写法只用于关联比较，数据库中的原始路径保持。Windows WSL UNC 数据库仍仅用于诊断，写操作需在对应 WSL 内执行。
