# Web 版使用说明

Web 版是 CLI 提供的本地浏览器界面，复用与桌面版相同的 Node 同步核心。它只在本机运行，不需要把 Codex 数据上传到远程服务；不提供桌面端的操作日志、原生目录选择器和应用更新。

本页说明 V1 界面。npm 安装得到的是已发布版本，未发布的 V1 功能需要对应本地构建；下载和版本状态以实际发布说明为准。

## 启动

Web UI 由 CLI 提供。安装 Node.js `16.20.2+` 后，安装本项目官方 npm 包并启动：

```bash
npm install -g @dailin521/codex-provider-sync
codex-provider web
```

默认地址：

```text
http://127.0.0.1:8791
```

默认会打开系统浏览器。可使用：

```bash
codex-provider web --port 8792
codex-provider web --no-open
codex-provider web --reset-access
codex-provider web --codex-home /path/to/.codex --sqlite-home /path/to/sqlite
```

运行中的服务按 `Ctrl+C` 停止。升级已安装的 CLI/Web UI：

```bash
npm install -g @dailin521/codex-provider-sync@latest
```

从仓库开发时使用 Node 24，在仓库根目录运行：

```bash
npm ci
npm run web:build
npm run web:start
```

## 同步 Provider

本工具只同步本地元数据，不负责登录或切换账号。已经通过其他工具切换 Provider 时：

1. 使用 CCSwitch 等常用工具切换 Provider，并确认 Codex 可以正常对话。
2. 回到 Web 版，在“概览”检查当前 Provider 和同步状态。
3. 在“同步当前 Provider”中选择“预览同步”，检查影响后确认；也可以点击“直接同步”立即执行。
4. 查看最终结果。部分完成时先查看跳过项和失败阶段，结束相关占用后重试；切回原 Provider 后如未对齐，再次同步。

“直接同步”的点击即为执行授权，没有第二次确认，但内部仍使用同一 Prepare/Apply、锁和备份校验。同步不调整历史模型，也不执行高级修复。

如果需要由本工具修改配置，在概览底部使用“单独切换 Provider”。它修改配置后仍会同步历史 Provider；自定义 Provider 必须事先已配置。默认采用 config 中目标 Provider 的模型，未配置时保留根模型；也可选择保留或手动指定根模型，三种方式均不改历史模型。

会话文件与本地聊天索引的数量可能因活动会话写入和索引时序短暂不同；这不一定表示 Provider 信息没有同步。请以页面显示的 Provider 分布和同步状态为准。

> **注意：** 同步用于对齐 Provider 信息，帮助旧会话重新可用，不是修复所有无法继续的原因。跨供应商继续旧会话时，目标后端可能无法解密会话中的 `encrypted_content` 推理内容，导致继续对话或压缩（compact）失败。遇到这种情况请切回原 Provider/account，或新建会话。

完成等浮动通知可点击内容或右上角 × 关闭；聚焦后也支持 Enter、空格和 Esc。不操作时仍会自动收起，关闭不影响操作结果和备份。

## 页面功能

- **概览：**显示当前 Provider、同步状态、备份数量和存储来源；同步与切换 Provider 都在这里完成。切换时可以使用该 Provider 配置的模型、保留当前根模型，或手动指定根模型。
- **备份与恢复：**统一设置保留数量（默认 2 份）、查看备份、恢复或手动清理。同步、切换、专项修复和自动同步共用该设置，每个 Codex Home 分别保留。设置保存在当前浏览器，不与桌面端或 CLI 共享；保存不会立即删除备份，修改前需停止自动同步，恢复所需的受保护备份可能超过数量。
- **聊天记录：**按项目组织主会话和折叠子任务，各项目独立加载更多；左侧列表、右侧消息独立滚动，窄窗口切换列表/详情。右键可复制会话 ID、继续命令等。只有明确选择会话后才读取正文，最多显示最近 200 条并提示截断；默认搜索名称、ID、项目等元数据，切换到正文搜索并提交后才扫描正文。搜索在按回车或点击搜索后执行，不逐字扫描。
- **存储配置：**管理受信任的 Codex 数据位置和聊天索引位置。默认配置由启动环境决定；需要其他位置时可创建具名配置。
- **高级功能：**仅在点击后执行完整只读检查。“专项修复”按需修正会话所属目录、补全用户消息标记或整理项目目录记录；模型名称统一放在独立的“高级调整”，不是故障修复。诊断入口只定位选项，不自动勾选；两组都需要预览、确认，日常同步不需要使用。
- **设置：**切换中文或英文、跟随系统/浅色/深色主题，管理自动同步，并可撤销当前浏览器连接。

首次进入加载数据；手动刷新、提交搜索、选择会话或完成相关写入后按需更新，不会在后台定时扫描。Diagnostics 必须主动点击，诊断与修复预览会显示当前阶段、检查数量和耗时；检查期间数据变化时会明确提示，是否重新检查由用户决定。界面支持键盘操作、清晰的焦点提示、减少动态效果和 200% 缩放。

“复制继续命令”只复制命令，不会启动终端。请在对应 Codex Home 环境和原项目目录执行，不保证跨 Provider 旧会话一定能继续。正文不会进入日志、诊断包或持久缓存。

## 本地安全边界

- 服务只监听 `127.0.0.1`，不要直接暴露到局域网或公网。
- 首次启动使用短时、一次性的配对链接；服务端只保存设备凭证哈希。使用“忘记此浏览器”或 `--reset-access` 可撤销授权。
- Core API 请求和响应使用统一版本协议；服务端校验来源、请求大小和存储配置状态。
- Production HTML 使用每响应随机 nonce 的严格 CSP；不允许远程脚本或跨源 Core 请求。
- 存储路径由本地服务管理。预览同步、切换、修复和恢复先显示预计改动并确认；直接同步以点击授权。恢复只能选择本应用创建的受管备份。
- Web UI 不能绕过共享核心逻辑中的锁、SQLite Home、WSL UNC、备份和恢复限制。

## SSH、无桌面环境和远程浏览器

服务不能直接暴露到公网或局域网。远程机器上使用时，只转发回环端口：

```bash
ssh -L 8791:127.0.0.1:8791 user@server
```

在远程 shell 中启动：

```bash
codex-provider web --no-open
```

命令会输出可点击的一次性配对链接。无桌面或纯 SSH 环境不会强制调用 `xdg-open`；即使浏览器打开失败，服务也会继续运行并输出配对链接。

## 注意事项

建议在同步或恢复前结束正在使用相关数据的 Codex 会话。同步中仍在使用的会话可能暂时跳过，其他内容会继续处理；这时结果会显示为“部分完成”，请在会话结束后再次同步。Restore 无法安全执行时会阻止恢复或进入恢复处理，不能套用普通同步的跳过语义。如果本地聊天索引 busy，请停止相关 Codex 写入后重试。

普通 Sync/Switch/Repair 写入后失败不自动全量回滚；查看结果和备份后选择重试或手动恢复。状态待刷新不等于工具正在写入，不要通过删除锁文件解决。
