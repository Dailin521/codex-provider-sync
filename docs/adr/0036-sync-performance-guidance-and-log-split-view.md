# ADR-0036：同步提速说明与操作日志双栏

- 状态：Accepted
- 日期：2026-09-08
- 范围：V1 共享 UI 展示与 Desktop 日志布局；不改 Core、CLI、IPC 或写入策略

## 决策

1. 概览同步区提供默认折叠的“如何加快同步”。说明合格等字节长度 Provider 可原地更新，不等长时流式复制文件；由 Core 自动选择，不提供 Fast 模式或一键改名。更改 ID 必须与配置/Provider 管理工具保持一致，显示名不是 ID；不要求用户改名、不承诺固定耗时。保留 PIO-1～PIO-6。
2. Sync/Switch 的结果窗口及 Desktop 日志详情仅在实际 `rewrittenSessionFiles >= 100` 时提供默认折叠的“查看提速建议”。阈值只控制展示，不是速度/安全门禁。只读现有实际计数，不根据耗时、预计数量或 Provider 名称推断策略；缺失/非法计数不猜测。进入页面或展开说明不调用 Core、不读取路径/正文、不修改配置。
3. 操作日志与 History 使用固定视口外壳；页面控件、日志列表、详情各自有界。宽度至少 1024 CSS px 时左列表、右详情独立滚动，分页与详情返回栏不随内容滚走。更窄窗口和 200% 等效视口使用列表/详情单页切换，不把长详情堆在列表底部；进入窄屏详情后隐藏列表标题/筛选，保留返回与手动刷新详情按钮，优先保证阅读空间。
4. 点击或键盘选择后按 ID 读取详情，仅重置详情滚动。宽屏保留列表焦点，窄屏聚焦可滚动详情；返回恢复所选行焦点与列表滚动。翻页、筛选、Profile/revision 变化清除选择，筛选从第一页一次请求；成功刷新后已移除的选择不继续显示旧详情，缺失日志不以摘要冒充详情。迟到的旧 ID 请求不能替换当前内容。
5. 详情先显示操作/时间/目标、结果与阶段时间线，再显示可复制关联编号。预计与实际数量、partial/失败原因、Profile/revision 跳转门禁完整保留。仅首次/手动刷新与既有当前操作推送；无定时器、后台轮询、额外诊断或日志 DTO 扩张。

## 验证

- `sync-performance-tip.vitest.tsx`：双语、默认折叠、展开零业务调用、实际计数阈值/非法值与 Repair/Restore 排除。
- `operation-logs-page.vitest.tsx`：延迟详情、手动刷新、独立滚动/返回焦点、翻页筛选移除选择、迟到/缺失详情、原日志字段和复制。
- `desktop-production-boundary.spec.mjs`：临时 userData 的合成日志，1366/1024 宽屏、683×384（200% 等效）/390×700 窄屏、无页面溢出、左右滚动隔离、返回与焦点；保留真实临时 Core Sync→Restore 回环。
