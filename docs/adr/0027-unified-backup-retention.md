# ADR-0027：统一备份入口和保留策略

- 状态：Accepted
- 日期：2026-09-07
- 依据：用户确认备份数量不应分散在多个页面，应只有一个备份入口和通道。

## 决策

1. “备份与恢复”是唯一管理入口：保留数量、备份列表、恢复与手动清理集中于此。移除 Sync/Switch/Repair 的数量表单，Settings 不增加第二份数量设置。概览只读说明当前规则。
2. 每个 Desktop 安装 / Web 浏览器保存一份应用级保留偏好，默认 2，范围 1–1000；对全部存储配置使用同一数值。备份仍归属于 Codex Home，别名配置和不同操作类型共享其备份池，不是每种操作各保留 N 份。不同 Home 不混放、不跨 Home 清理。
3. UI 操作表单不再拥有 keepCount。App 编排在 Prepare 时统一注入已保存偏好，直接同步与预览相同；已生成计划仍使用 Prepare 时的值，不能在 Apply 偷换策略。
4. StartWatch 增加可选正整数 keepCount，贯通内部每次 ProviderSync，默认仍为 2。运行中的 Watch 保持启动时参数。用户明确保存设置时只读检查本 Core 进程全部 Watch；仍有活动 Watch 则不保存，提示先停止。检查失败或持久化失败不变更内存规则、不假报保存成功。不增加后台轮询。
5. 保存偏好本身不清理备份。手动清理使用已保存规则，保留影响预览和确认；未保存草稿时禁止清理。原有 keep=0 手动能力改为高级区明确的“删除全部可清理备份”按钮和独立确认，不允许把自动备份数量设为 0。
6. 底层继续使用既有 UndoBackup、受管备份目录和 prune；不另造 BackupManager，不复制 Provider/SQLite 算法。Restore 的恢复前快照、独立 journal 与受保护备份保持原语义：不强行按 N 删除恢复证据，实际数量可以超过 N。
7. 偏好只存 Host 的本地应用/浏览器数据，不写 Codex config 或认证文件，不是跨 Web/Desktop/CLI 同步的全局配置。CLI 显式 `--keep` 与默认 2 兼容，Legacy .NET 不改。

## 验收

- 唯一可编辑保留数量；保存后 Sync/Switch/Repair/Watch 使用同一值，跨页面、存储配置和应用重开保持。
- 修改草稿、保存和保存失败都不能触发 prune；清理预览使用已保存数量，输入 0/负数/小数/超限拒绝。
- Watch 活动、查询失败及存储失败不保存；Watch keepCount 端到端采用已输入值，缺省行为不变。
- Restore/PIO 门禁继续有效；测试仅临时 fixture。本地验证不等于发布/跨平台实机证据。
