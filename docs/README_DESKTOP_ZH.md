# Codex Provider Sync 桌面版

V1 Electron 是面向用户的主桌面界面，用于在切换 Provider 后对齐本地会话文件和聊天索引，帮助因 Provider 信息不一致而无法正常使用的旧会话重新可用。同步不保证跨 Provider 解密或继续。构建目标为 Windows、macOS 和 Linux；可下载平台以实际 Release 资产为准。本地构建不代表已经公开发布、签名或启用更新通道。

## 第一次使用

1. 安装对应平台包，或解压并保留完整程序目录；Windows 运行 `Codex Provider Sync.exe`，不要只复制一个 EXE。
2. 在“概览”核对当前 Provider、Codex 数据位置、聊天索引位置和实际数据库文件。
3. 已用其他工具切换 Provider 时，使用“同步当前 Provider”中的预览或直接同步。
4. 查看最终结果；有跳过或部分完成时，结束相关占用后重试。需要撤销时到“备份 / 恢复”选择备份。
5. 日常同步不需要进入“高级功能”。

宽屏概览上方显示状态和 Provider 分布；当前存储配置在左、同步按钮在右。“单独切换 Provider”位于最底部，窄窗口自动上下排列。

完成等浮动通知可点击任意位置（含右上角 ×）关闭，也可聚焦后按 Enter、空格或 Esc；不操作时仍会自动收起。关闭通知不会删除操作结果、日志或备份。

## 同步与切换 Provider

### 同步当前 Provider

如果已通过其他工具修改 `config.toml`，此操作将当前 Provider 同步到会话文件和本地聊天索引，不修改 config 或历史模型。

- **预览同步**：先查看影响和备份提示，确认后执行。
- **直接同步**：点击即执行，没有第二次确认；内部仍完成同一套计划、锁、复核和备份检查。

自定义 Provider 必须已在配置中定义；未定义时应用会停止，不会擅自切回 OpenAI。没有实际改动时不创建备份。

### 单独切换 Provider

这里不是“只改配置”：应用先修改 config，再同步历史中的 Provider 信息。选择目标后点击“预览切换”，确认后执行。

目标默认跟随当前 Provider；首次读取和手动刷新只更新未编辑的目标，不覆盖你已填写的值。切换存储配置后重置目标和模型选项。“最近成功使用”来自当前配置仍可用的成功切换记录，点击仅填入目标，不自动执行。

| 模型处理方式 | 会做什么 |
| --- | --- |
| 使用 config.toml 中该 Provider 的模型 | 采用 `[model_providers.<id>].model`，未配置则保留当前根模型，不联网查询 |
| 保留当前根模型 | 不修改 config 根级 `model` |
| 手动指定根模型 | 写入所填模型名，不验证远端是否支持 |

三种方式都不修改历史会话记录的模型。确需统一名称时，使用“高级功能 → 高级调整 → 统一历史模型名称”；历史模型不同不代表故障，此项不会重新生成回答。

### 速度和时间戳

Provider 同步的业务扫描只解析首行。安全、唯一可定位且 JSON 字面量字节等长的 Provider 自动原地更新；其余有效首行流式替换，正文保持逐字节不变。大文件变长替换需要复制正文，耗时会增加。

概览的“如何加快同步”可按需展开，软件自动选择写法，没有模式开关。无需为了正常同步改名；若自行调整 ID，必须与 config 和 Provider 管理工具一致，只改显示名称无效。

备份、落盘和文件修改时间恢复不会为提速取消。预览复用同轮首行事实，执行仍重新检查；不会改动消息时间或线程索引的更新时间。[详细工作原理](WORKING_PRINCIPLE_ZH.md#4-provider-的两种落盘方式)

## 备份与恢复

备份数量只在“备份 / 恢复 → 备份设置”修改，默认 **2 份**。同步、切换、专项修复和自动同步共用此设置，每个 Codex Home 分别保留，不是每种操作各保留 2 份。

- 保存数量不会立即删除备份；修改前需停止自动同步，设置在重启后保留。
- 手动清理先显示预计影响并确认；“删除全部可清理备份”是独立操作，不把自动保留数设为 0。
- 恢复依赖的受保护备份可能超过数量，不能强行删除来凑数。
- 桌面、Web 浏览器和 CLI 不共享偏好。
- 备份读取失败显示重试，不会显示为“没有备份”。

恢复时选择已有备份及其实际保存的内容，先预览再确认。未保存的内容不可恢复。恢复前会保存目标当前状态，再进行独立恢复核验；这与普通同步失败后的手动重试不同。

迁移聊天索引需要明确目标存储配置与迁移确认，不恢复旧 config 或工作区设置；如果同时选择会话记录文件，它们仍恢复到来源 Codex Home，不是把所有聊天文件搬到目标目录。

## 聊天记录

- 左侧按项目组织主会话和折叠子任务，各项目/父会话按需加载更多；右侧显示聊天消息，两边独立滚动。
- 整行选择会话；右键菜单提供复制会话 ID/继续命令、会话信息、文件定位与父会话导航。项目右键可设置本地显示名，不回写 Codex 数据。
- 只有明确选择后才读取正文，最多显示最近 200 条并提示截断。助手消息支持 Markdown、代码块和复制；窄窗口在列表/详情间切换。
- 默认搜索名称、ID、项目等元数据；切换到“聊天正文”并按回车或点击搜索后才扫描正文，不逐字搜索。
- 草稿筛选未提交会提示；“清除筛选”返回全部会话，不自动扫描正文。详情失败可直接重试，不丢失左侧展开状态。
- 标题优先使用已保存的标题索引、当前数据库标题和首行 metadata；缺失时用可识别类型/标识兜底，不读首条消息猜标题。
- “文件更新”不是最后聊天时间。

“复制继续命令”只复制 `codex resume <会话ID>`，不启动终端。请在对应 Codex Home 环境和原项目目录执行；缺少原始 ID 时不能用内部列表标识恢复会话，更换 Provider 后也不保证旧加密内容可以继续。

## 操作日志

新同步失败记录会尽可能显示实际失败阶段和底层错误码，包括尚未开始更新文件就失败的情况。反馈问题时可复制关联 ID；旧日志没有记录的详情不会补造。

左侧选择操作，右侧查看详情，两个区域独立滚动；窄窗口点击进入详情，再用“返回操作列表”返回。支持按存储配置、操作类型和结果筛选。

日志记录同步、切换、专项修复、恢复、备份清理、诊断/导出、自动同步、更新、配置管理和 Core Runtime 故障，不记录普通状态刷新或聊天浏览/搜索。保存在应用 userData，不在 Codex Home。

详情包括：

- 目标 Provider、预计改动、实际写入和跳过数量、结果、警告、失败阶段及备份。
- 切换计划中的 Provider/根模型前后值和模型策略；计划与最终结果分开，不能仅凭计划认定已修改。
- 实际处理总耗时、包含确认等待的总时长，以及阶段时间线。
- Windows 新同步/切换及自动同步的文件分项耗时：复制、落盘、替换、清理、时间戳恢复。底层技术时间有包含关系，不能直接相加。
- 可复制的关联编号，用于排查同一请求、计划和操作。

日志只首次加载/手动刷新，不后台轮询；返回后未看到新记录时点击刷新。旧日志或未测到的操作不补造详情/零耗时。关闭确认框记为放弃，崩溃/重启后遗留操作记为中断，不冒充成功。归档最多 5 个文件、每个 5 MiB，较早记录会轮转；诊断导出会包含最近的结构化日志，不包含聊天正文。

## 存储位置

概览显示当前 Codex Home、SQLite Home 和实际数据库文件完整路径；它们来自状态快照，手动刷新可重新读取。目录与最终 DB 文件不是同一个概念：默认布局仍可能使用旧位置的 state DB。

默认配置由启动环境决定，不能直接编辑或删除。需要其他位置时新建具名配置：

1. 填写名称，并通过目录选择器选择 Codex 数据目录。
2. 可选聊天索引目录；留空时按 config 的 `sqlite_home` → `CODEX_SQLITE_HOME` → `<Codex Home>/sqlite` 解析。
3. 保存后自动选中新配置，相关概览、聊天列表和备份随之更新。可以编辑/删除具名配置，或在资源管理器中显示目录。

只有默认 SQLite 布局允许回退到 `<Codex Home>/state_5.sqlite`；明确指定的位置缺 DB 不会偷偷改用另一份。写操作或自动同步活动期间不能修改配置，旧预览在配置 revision 变化后失效。Windows WSL UNC SQLite 仅诊断；写入请转到 WSL 内的 CLI。

## 高级功能

这些功能用于少见问题，日常同步无需勾选。

| 功能 | 实际改动 |
| --- | --- |
| 修正会话所属目录 | 按聊天文件记录修正索引中的目录，不移动文件 |
| 补全用户消息标记 | 补全索引中已有用户消息的标记，不增删消息 |
| 整理项目目录记录 | 整理保存的工作区设置并保留设置备份，不删除项目目录；作用于全存储配置，并包含会话目录修正 |
| 高级调整：统一历史模型名称 | 按 config 当前根模型调整历史模型名称；没有根模型时不能准备 |

先手动诊断或选择需要的项目，再预览、确认。默认全不选，“查看修复”只定位对应选项，不自动勾选或执行；普通同步失败也不会自动升级为修复。

诊断、修复预览和模型调整预览显示当前阶段、已检查数量和耗时；百分比是当前步骤进度，不是整个任务的完成度。事实完整扫描每次只一轮，记录完整性检查另有阶段；数据变化会保留观察并提示未完整核验，不反复重扫。Apply 仍独立复核，不能直接拿旧诊断结果写入。

预览区“索引字段改动”可包含同一会话多个字段；“受影响会话”已去重。“工作区设置改动项”是设置类别，不是文件夹数量。全局修复仍可查看最多 100 个会话的只读明细，但不能限定到其中几个。

当前不提供会话记录序号改写、历史显示索引重建或加密内容修改。

## 状态、结果与重试

| 提示 | 含义和下一步 |
| --- | --- |
| 尚未验证 / 状态待刷新 | 不代表正在同步；点击重新读取，核验前暂不能修改，不要删除锁文件 |
| 正在使用的会话 | 当前 Home 中 Codex writer 持有的会话，包括等待输入、子会话及已对齐会话；不是生成回复数。目前支持 Windows writer 观察，无法读取时显示未知 |
| 本次将跳过的会话 | 本次同步写入受阻的目标，与“正在使用”不是同一个计数 |
| 部分完成 | 查看失败阶段、错误码和备份，返回重新预览/同步，或手动恢复；应用不自动全量回滚 |
| 最终 Provider 检查未完成 | 回概览手动刷新，不把未核验说成已同步 |
| 旧会话无法继续 | 可能需要原 Provider/账号解密；可回到原环境或新建会话 |

取消只在首次写入前生效；开始写入后请等待结果，不要强制结束进程。配置变化或备份已被清理时需要重新选择，旧日志的重试入口只导航，不重放旧计划。

## 自动同步、语言与窗口

数据首次加载、明确查询或手动刷新；相关写入后会更新状态/历史/备份，操作日志另行手动刷新。没有后台数据轮询，Diagnostics 不会随打开页面自动启动。

正常聊天追加不会让 Provider 概览反复要求刷新。如果 Provider 配置、存储位置或会话的 Provider 信息确实改变，仍需重新检查；同步时会再次检查并跳过无法安全写入的会话。

Watch 需在“设置”主动开启；当前状态按存储配置显示。指向同一 Codex Home 的配置共用监听，关闭时共同停止；选项及执行/停止日志归首次启用的配置，需要时在日志选择“全部配置”。

语言支持中文/英文，默认跟随系统；主题支持跟随系统、浅色、深色。支持键盘、焦点提示、减少动态效果和 200% 缩放。窗口记住大小、位置和最大化状态，副屏断开时回到可见区域；偏好保存在应用 userData。

## 程序安装、更新与体积

若显示“上次操作已结束”，可正常预览或同步，程序会在写入前重新检查并清理已确认失效的锁。“存储锁需要检查”则表示尚不能确认是否有其他程序在写入：先结束其他同步/恢复操作，再点“重新检查”；仍存在时导出诊断包反馈，不要手动删除锁文件。

“设置 → 更新”可检查更高的正式 Electron 版本，不把旧 .NET 单 EXE 当成新版。

- 每个本地日期的首次启动检查一次，发现新版才弹窗；当天后续启动不自动再查，连续运行跨日也不另设检查。失败后可手动重试，不自动下载或安装。
- 便携版/本地打包版打开官方下载页。退出后解压完整新版到新目录，不要只替换一个 EXE。
- 已启用正式更新通道的安装版可按需下载，再确认重启安装；写操作、自动同步或未完成恢复会阻止安装。
- 设置更新区和新版弹窗可选“不再提醒此版本”；重启后保留，下个新版仍提醒。仍可手动检查/更新，也可在设置中恢复该版本提醒。
- 1.0.2 修复安装版检查更新立即失败的问题。受影响的 1.0.1 安装版无法自行检查到修复，请从官方下载页手动安装 1.0.2 一次，详见[升级说明](release-notes/v1.0.2-zh.md)。线上跨版本下载安装仍待独立验收。
- **旧 Windows .NET 的单 EXE 自更新不能直接升级到 Electron。** 首次迁移需安装/解压完整新版；不把 NSIS 安装器冒充旧 EXE，不承诺已经完成线上跨版本升级验证。
- 更新程序不替换 Codex 数据。下载安装方式、签名与更新通道以实际发布说明为准。

Electron 运行环境占主要体积，下载大小与解包占用不同。Windows 当前预算为 ASAR ≤ 3 MiB、解包目录 ≤ 280 MiB、NSIS ≤ 105 MiB、便携 ZIP ≤ 130 MiB，实际以该次产物测量为准，不承诺 50 MiB。

完整 Chromium 许可证保存在 `LICENSES.chromium.zip`，解压 HTML 可离线阅读；`THIRD-PARTY-NOTICES.txt` 提供说明与原文校验值。请保留归档和运行依赖，不能仅保留 EXE。

## 数据与开发边界

应用不读取、复制、记录 `auth.json`、凭据或令牌。聊天正文仅在显式 History 交互、手动诊断或指定修复的对应范围处理，不进入操作日志、诊断包或持久缓存。Provider 同步不修改消息、标题、顺序或线程 `updated_at`。

开发使用 Node 24；自动化只用临时数据。完整命令见 [贡献指南](../CONTRIBUTING.md)。本地隐藏窗口验证：

```powershell
npm ci
npm run architecture:check
npm run desktop:test
$env:CPS_DESKTOP_WINDOW_DISPLAY = "hidden"
npm run desktop:test:e2e
```
